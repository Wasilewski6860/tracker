# Проверки и критерии приёмки

## 1. Иерархия задач

- [ ] Нельзя назначить задачу родителем самой себя.
- [ ] Нельзя создать цикл из двух задач.
- [ ] Нельзя создать цикл из трёх и более задач.
- [ ] Нельзя назначить родителя из другого проекта (если межпроектная иерархия не поддержана).
- [ ] Нельзя создать Sub-task без допустимого родителя.
- [ ] Нельзя создать дочернюю задачу у Sub-task.
- [ ] Изменение типа не нарушает существующие связи.
- [ ] Удаление родителя выполняет утверждённое поведение и не оставляет некорректное дерево.

## 2. Права

Проверить каждый endpoint и UI для owner/member/viewer:
- [ ] Просмотр проекта и задачи.
- [ ] Создание задачи.
- [ ] Изменение полей.
- [ ] Переход статуса.
- [ ] Комментарий.
- [ ] Удаление задачи.
- [ ] Управление участниками.
- [ ] Настройка проекта и workflow.
- [ ] Доступ к вложениям.

Запрос напрямую к API не должен позволять обойти ограничения UI.

## 3. История и комментарии

- [ ] Создание задачи создаёт activity event.
- [ ] Изменение каждого поддерживаемого поля фиксирует старое и новое значение.
- [ ] Переход статуса фиксируется.
- [ ] Создание комментария фиксируется в activity в той же транзакции.
- [ ] Редактирование/удаление комментария отражается согласно политике аудита.
- [ ] События стабильно сортируются при одинаковом timestamp.
- [ ] Ошибка операции не оставляет частично записанное состояние.

## 4. Связи задач

- [ ] Нельзя связать задачу с самой собой.
- [ ] Нельзя создать дублирующую связь.
- [ ] Симметричные связи отображаются с обеих сторон.
- [ ] Направленные связи корректно показывают обратную формулировку.
- [ ] Удаление задачи не оставляет висячие ссылки.

## 5. Поиск и списки

- [ ] Поиск находит задачи за пределами первой страницы.
- [ ] Фильтры комбинируются на сервере.
- [ ] Сортировка стабильна.
- [ ] Пагинация не пропускает и не дублирует записи при обычном использовании.
- [ ] Количество задач соответствует доступным результатам.
- [ ] Пустой результат имеет понятное состояние.

## 6. Frontend и сеть

- [ ] 401 приводит к корректному сценарию авторизации.
- [ ] 403 показывает отсутствие прав, а не сетевую ошибку.
- [ ] Ошибки валидации показываются рядом с действием/полем.
- [ ] 500/502 и отсутствие сети не сбрасывают пользователя как при 401.
- [ ] Пустой и не-JSON ответ обрабатываются безопасно.
- [ ] Быстрое переключение проекта/задачи не показывает устаревший ответ.
- [ ] Повторное нажатие не создаёт дублирующие операции.
- [ ] Оптимистичный rollback не затирает другие подтверждённые изменения.
- [ ] Модальные окна корректно управляют фокусом и клавиатурой.

## 7. Production

- [ ] Нет дефолтного JWT secret и тестового пароля БД.
- [ ] Секреты отсутствуют в репозитории и Git history либо скомпрометированные секреты заменены.
- [ ] HTTPS настроен.
- [ ] Secure Cookie включён в production.
- [ ] PostgreSQL и Mailpit не доступны из внешней сети.
- [ ] SMTP настроен и проверен.
- [ ] Контейнеры перезапускаются после сбоя.
- [ ] Логи ротируются.
- [ ] Healthcheck проверяет реальную готовность.
- [ ] Бэкап создаётся автоматически.
- [ ] Восстановление из бэкапа проверено.
- [ ] Чистая установка зависимостей и сборка воспроизводимы.

## 8. Сквозной сценарий регрессии

1. Создать пользователя и проект.
2. Добавить участника с ролью member и участника viewer.
3. Создать Epic, Story, Task и Sub-task согласно утверждённой иерархии.
4. Проверить недопустимую иерархию и циклы.
5. Назначить исполнителя и изменить приоритет/срок.
6. Переместить задачу по разрешённому workflow.
7. Попробовать запрещённый переход.
8. Добавить комментарий и проверить журнал.
9. Создать связь с другой задачей и проверить обратное отображение.
10. Проверить права owner/member/viewer на прямых API-запросах.
11. Удалить участника с назначенными задачами и проверить утверждённое поведение.
12. Проверить удаление родителя.
13. Найти задачу, находящуюся за пределами первой страницы.
14. Перезапустить контейнеры и убедиться, что данные сохранились.
15. Восстановить резервную копию в отдельном окружении.
