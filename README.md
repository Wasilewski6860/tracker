# Трекер

Упрощённый трекер задач: проекты, задачи с ключами, доска, разрешённые переходы статусов, комментарии и журнал. Клиент и API разделены. Локально используется `docker-compose.yml`, на своём сервере — `docker-compose.prod.yml`.

## Что уже есть

- Регистрация с подтверждением почты, вход и сброс пароля по письму
- Проекты с ключом (`WEB-12`)
- Роли: владелец, участник, наблюдатель
- Типы: эпик, история, задача, ошибка, подзадача. У подзадачи есть родитель
- Статусы: бэклог, к выполнению, в работе, на проверке, готово. Переход только по цепочке
- Срок задачи
- Доска с поиском и переносом карточек
- Комментарии и журнал изменений

Спринты и свои поля — следующие шаги. В проект можно пригласить только уже зарегистрированного человека: роль выбирает владелец внизу доски.

Локальная почта — Mailpit. Письма подтверждения и сброса пароля не уходят в интернет, их видно на http://localhost:8025.

## Разработка с горячей перезагрузкой

Нужны Node.js 22+ и Docker.

```powershell
cd $HOME\tracker
docker compose up postgres mailpit -d
npm install
npm run dev
```

Интерфейс: http://localhost:5173  
API в разработке слушает порт 3001: на этой машине 3000 уже занят другой программой.

Файл `.env` уже подготовлен для локальной базы на порту 5433, чтобы не пересекаться с другим Postgres на 5432. Образец лежит в `.env.example`.

## Локальный полный стек

```powershell
docker compose up --build -d
```

Интерфейс: http://localhost:8080. Почта разработки: http://localhost:8025. База доступна на порту 5433. Это только для своей машины.

Остановка: `docker compose down`. Том `pgdata` сохраняет данные. `docker compose down -v` удаляет его вместе с задачами.

## Свой сервер

Скопируйте `.env.production.example` в `.env.production` и подставьте свои значения. Пароль базы не `tracker`, секрет длиннее 32 символов. Приложение слушает только `127.0.0.1:8080`: перед ним нужен HTTPS-прокси (Caddy или nginx), который проксирует сайт на этот адрес. Почта — ваш SMTP, не Mailpit. База наружу не публикуется.

```powershell
docker compose --env-file .env.production -f docker-compose.prod.yml up --build -d
```

Если API стартует с тестовым секретом или `COOKIE_SECURE` не включён, процесс завершается с ошибкой.

Копия базы:

```powershell
$env:COMPOSE_FILE="docker-compose.prod.yml"
$env:POSTGRES_USER="tracker"
npm run backup
```

Файл появится в `backups/`. Рядом храните каталог `data/attachments`: в дамп базы файлы не входят. Храните копии не только на этом сервере. Восстановление в ту же базу:

```powershell
npm run restore -- backups/tracker-....sql
```

Проверяйте восстановление на отдельном запуске, не поверх единственной рабочей базы. Скрипт оставляет 14 последних файлов.
